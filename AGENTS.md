# Project delivery

- The user requests a GitHub Release for each completed software version update. After appropriate tests and a Windows portable build, publish the versioned executable, SHA-256 checksum, usage notes, test report and default replay CFG to https://github.com/xiaoiii/cs2-demo-desk. Do not replace older releases or claim that unsigned builds are signed.
- Verify the release tag matches the committed source and check uploaded asset names and sizes. Keep credentials, personal profiles, downloaded demos and test-results out of Git.
- Halo publication is authorized for the requested project article. Use the user's supplied server access; do not put SSH keys or Halo tokens in repository files or logs. A new release does not by itself authorize unrelated changes to the server.
